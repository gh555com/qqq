# 🤖 AI三级发布系统

## 📋 系统概述

这是一个智能化的三级发布系统，通过简单的指令即可完成不同程度的代码发布：

- **q3**: 快速代码保存（仅版本递增，不发布）
- **q1**: 半自动化PR流程（创建PR等人工合并）
- **q2**: 完整自动化发布（直接发布到市场）

## 🎯 使用方法

在GitHub Issue或Discussion中发送以下指令：

```
发布q3    → 快速保存当前代码版本
发布q1    → 创建PR等待人工合并审查
发布q2    → 完整自动化发布到市场
```

## ⚙️ 系统特点

### 🔧 智能化处理
- 自动版本号管理
- 智能提交类型识别
- 多平台自动构建
- 一键触达完整流程

### 🛡️ 安全控制
- 主分支保护机制
- 人工审查环节可选
- 完善的错误处理
- 详细的操作日志

### 🚀 高效便捷
- 零代码操作
- 零命令行使用
- 三步完成发布
- 状态实时反馈

## 📊 流程说明

### q3快速保存流程
```
用户指令 → 版本递增 → 代码提交 → 完成
```

### q1半自动化流程
```
用户指令 → 创建分支 → 提交代码 → 创建PR → 等待合并 → 自动触发q2
```

### q2完整发布流程
```
用户指令/PR合并 → 版本分析 → 多平台构建 → GitHub Release → 市场发布 → 完成
```

# 🤖 AI发布指令系统文档

## 📋 三级发布机制说明

### **q3 - 快速代码保存**
```
触发条件: 用户说"发布q3"
执行动作:
- 提交当前代码到qq分支
- 创建小版本号递增（patch级别）
- 仅保存到云端，不触发任何发布流程
- 不创建GitHub Release
- 不发布到Marketplace

适用场景:
- 小bug修复
- 代码重构
- 实验性功能开发
- 需要快速备份当前进度
```

### **q1 - 半自动化PR流程**
```
触发条件: 用户说"发布q1"
执行动作:
- 从当前qq分支创建新分支: release/v{version}
- 自动提交所有更改
- 在GitHub上创建Pull Request
- 等待用户在网站手动合并
- 合并后自动触发q2完整流程

适用场景:
- 重要功能更新
- 需要代码审查的变更
- 团队协作开发
- 需要讨论的改动
```

### **q2 - 完整自动化发布**
```
触发条件: 用户说"发布q2" 或 q1 PR被合并
执行动作:
- 智能版本号递增（根据提交类型）
- 多平台并行构建
- 创建GitHub Release
- 发布到VS Code Marketplace
- 生成变更日志
- 发送发布通知

适用场景:
- 正式功能发布
- 重要bug修复
- 生产环境更新
```

## 🎯 指令使用规范

### **用户指令格式：**
```
发布q3    → 快速保存当前代码
发布q1    → 创建PR等待人工合并
发布q2    → 完整自动化发布
```

### **AI执行逻辑：**

1. **监听用户指令**
2. **解析指令类型**（q1/q2/q3）
3. **执行对应流程**
4. **反馈执行结果**

## ⚙️ 技术实现要点

### **分支管理策略：**
```
qq              ← 主分支（生产环境）
release/*       ← 发布分支（由q1创建）
dev/*           ← 开发分支（日常开发）
hotfix/*        ← 热修复分支
```

### **版本号处理：**
- q3: patch版本递增（15.17.28 → 15.17.29）
- q1/q2: 根据提交内容智能递增（feat→minor, fix→patch, breaking→major）

### **触发机制：**
- q3: 直接push到qq分支
- q1: 创建PR到qq分支
- q2: PR合并事件触发 或 直接触发

## 🛡️ 安全控制

### **权限要求：**
- AI需要GitHub写权限
- 需要VS Code Marketplace发布权限
- PR创建需要适当的repo权限

### **保护机制：**
- 主分支保护规则保持不变
- 所有操作都有详细日志
- 失败时自动回滚并通知

## 📊 状态反馈

### **执行成功反馈：**
```
✅ q3执行完成：代码已保存至版本v15.17.29
✅ q1执行完成：PR已创建，请前往GitHub合并
✅ q2执行完成：新版本v15.18.0已发布
```

### **执行失败处理：**
```
❌ 执行失败：[具体错误原因]
🔧 建议操作：[解决方案]
```

这个系统让用户可以根据不同需求选择合适的发布方式，既保证了灵活性又维持了自动化效率。
